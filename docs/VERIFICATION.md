# 検証結果 — SILICON DRIFT 1.1.0

## 結果

- **Node.jsテスト: 32 / 32 成功。** 基板生成、座標、起動監視、分離構成、HTTPサーバー、配信用コピー、ワークフローの主要設定を確認しました。
- **Chromiumブラウザテスト: 45 / 45 成功。** 画面の表示・操作・再生成・起動診断を確認しました。
- 通常操作中の想定外のJavaScript／コンソールエラー: **0件**。
- GitHub Pages用の `_site/` にコピーされた公開用12ファイルは、元の分離ファイルとバイト単位で一致しました。
- GitHub ActionsのYAMLを解析し、push対象がmainであること、Pagesの権限とアーティファクトのパスを確認しました。GitHub上で実行したものではありません。

## 分離による変更の確認

配信するHTMLには、アプリのインラインJavaScriptやstyle要素を含めていません。CSS・JavaScript・アイコンは外部ファイルとして相対参照します。デプロイ時のHTMLへの再結合もありません。

`math.js`、`geometry.js`、`renderer.js`、`world.js`、`controls.js` と `style.css` は、スマホ向け修正版1.0.1の分割ソースと同一です。`app.js` は冒頭コメントと表示バージョンだけを変更しました。起動監視には、分離スクリプトの読み込み失敗を知らせる処理を追加しました。

## 実際のテスト方法と制約

### Node.js／HTTP

Node.js 22.16.0で実行しました。同梱サーバーを起動し、HTTPリクエストでHTML・CSS・JS・アイコンの応答とMIME型を確認しています。`/SILICON-DRIFT/` の相対参照、末尾スラッシュへのリダイレクト、クエリ付きURL、HEAD、未知のパス、開発用ファイルを配信しないことも確認しました。

### ブラウザ

Linux上のChromium 144.0.7559.96、仮想ディスプレイとソフトウェアGPUを使用しました。スマホは390×844および844×390、DPR 3、タッチ有効のエミュレーションです。**iPhone実機・Safariではありません。**

この実行環境ではブラウザのURLナビゲーションが管理ポリシーで拒否されるため、今回のブラウザテストは `SD_BROWSER_FIXTURE=1` で実施しました。HTMLを `set_content` で読み込み、テスト用のbase URLを設定し、実際の分離CSS・JSを個別のリクエスト応答として与えています。シード指定の再現には、テスト応答内だけでクエリを置き換えています。

そのため、**ブラウザからHTTPサーバーへアクセスする一連の動作や、GitHub Pagesの公開URLへのアクセスを、実環境で確認したものではありません。** HTTP応答とブラウザ内の分離読み込みはそれぞれ確認していますが、制約のないブラウザでの直接URL検証は残っています。配布するHTMLにテスト用base URLや故障注入コードは含めていません。

スマホサイズでは初期描画、軽量設定、探索開始、1本指の回転・2本指のピンチ・移動スティックを確認しました。指のジェスチャーはCDPのタッチイベントで入力しています。その後の設定・シード・没入モード等はエミュレーション画面上でのクリック操作です。連続したCDPジェスチャー直後のtapによる設定ボタン試験は安定せず、実機タップ操作を全て確認したという意味ではありません。製品のタッチ処理自体は前版から変更していません。

PCサイズではマウス・キーボード、視点切り替え、品質切り替え、シード再生成、ページ復帰を確認しました。故障試験はWebGL未利用、JS構文エラー、外部JSの欠落、CSPによる実行ブロック、JavaScript無効、描画フレーム停止、コンテキスト喪失です。これらは検証用に作った条件で、報告された端末の原因を特定したものではありません。

## 未実施

GitHubリポジトリへのコミット・push、Pagesの設定変更、GitHub Actionsでの実行、公開先へのデプロイは行っていません。実機のSafari、iOSのファイルプレビュー、実機性能・電池消費、組織固有のGitHub権限設定も未検証です。

## 記録と再実行

- `node-test-results.txt`: Node.jsテストの実行結果。
- `browser-verification.json`: ブラウザテスト45項目と実行環境。
- `mobile-fix-preservation.json`: 前版から維持した描画・生成・操作ロジックの確認。

通常のローカル環境では `npm test` と `python tests/browser.test.py` で実行します。Python側はPlaywright・Chromiumが別途必要です。通常モードは同梱HTTPサーバーを自動起動してURLを開きます。ブラウザテストはPagesワークフローには含めていません。

今回の制約付き実行環境で使用したコマンド:

```sh
npm test
npm run package:pages
xvfb-run -a env SD_BROWSER_FIXTURE=1 python tests/browser.test.py
```
